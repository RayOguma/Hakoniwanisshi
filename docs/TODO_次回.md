## 作るときに忘れないこと
- `story.ts` の `answer`(開発用: 途中から始めるとき、解いた形にする)も書く
- `?start=N` の番号は、幕間もふくめて数える(問題17は 22)
- 結末で、だれが残ったかは `model.flags` の `stayH`・`stayV`(`story.ts` の `stayer`)。残った子の場所・となりのヘッドの場所は、`page.ts` の `step` が、この印を見て、毎こま置く(セーブから戻っても、同じ形になるように)。引っ越しが済んだ印は `moved`、戸口は `door`
- 容量に数えない場所は、`Area.free`(引っ越しのリンク)
- `CHATTER`(ふだんの一言)は、解いた問題の数で選ぶので、問題を足したら各住人に1つずつ足す
- 暗転して行う演出(「次の日」など)は、`main.ts` の `FADES` に、演出の名前と出す字を書く
- 主人公が住人に話しかけるのは、選択肢だけ(主人公のせりふは心の声)
- ページに足す物のクラス名は、日誌の記事(`.post`)やカード(`.card`)など、ページにもうある名前とぶつからないようにする(問題9で、柱を `.post` にして、記事が崩れた)
- 同じ CSS の決まり(セレクタ)を、2つの場所に書かない(元に戻す・セーブが、セレクタごとに覚えているため)
- ほかのタブを見ているあいだは、ページの位置が測れない(`offsetLeft` などが 0 になる)。位置に合わせて住人を動かす処理は、`world.clientWidth` が 0 のとき、何もしないこと(問題10で、住人がページの下へ飛ぶ不具合が出た)
- 物語の進みぐあいの印は、`model.flags`(セーブされる)
- 会話の中の演出のうち、ソースの中身を変えるもの(石を詰める・リンクが字になる)は、`main.ts` の `mainFx`。途中から始めるときも、ここを通る
- 解けたときの会話を、場合で変えるときは、`Problem.doneAlt`。ヒントを、進みぐあいで いくつにも変えるときは、`Problem.hintsFn`
- 荷造り(`model.flags` の `packed`)のあとに書き換えられる物を足すときは、`model.tied` の「ひもの外」に入れる
- 夜の場面は、住人を決まった所に置くが、ソースを開いてページの幅が変わると、庭の中の物(家・看板)との位置が、少しずれる(前からの弱点。直すなら、置いた場所を、庭の幅に合わせて覚える)
- 容量メーターが出たあとは、ソースの字が増える仕掛けを足すと、メーターが動く(`model.size()`)。新しい場所(`makeAreas`)を足すと、その字数も数えられる。メーターが出る前に開く場所なら、はじめの はみ出しは同じになる(`meterOn` が合わせる)が、**メーターが出たあとに開く場所は、その分だけ字数が増える**ので、気をつける
- 問題のあとに続く、問題ではない流れ(検索して調べる、など)は、`Problem.afterFlow` と、`main.ts` の流れの関数(`findHome`)。途中から始めるときの「済んだ形」も、`startFrom` に書く
