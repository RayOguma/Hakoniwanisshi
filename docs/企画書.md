# 企画書:箱庭日誌 〜定年エンジニアの手作りページ〜

> タイトルは**「箱庭日誌 〜定年エンジニアの手作りページ〜」**(決定。管理人のページの題=ゲームの題。直しながら日記=日誌を読むゲームで、最後の日記が閉じられていない=日誌が途中で終わる結末とも重なる) / 開発前の構想メモ。決定事項と未決事項を分けて記載する。

---

## 1. コンセプト

Webページ(HTML/CSS)の中に住む「住人」たちと会話しながら、コードを書き換えて彼らの暮らしを助けるストーリー重視の謎解きゲーム。

- 住人は、自分たちがHTMLの世界に住んでいることを知らない。困りごとは彼らの言葉で語られる。
- プレイヤーは、住人の言葉を**コードに翻訳する人**。会話で困りごとを聞き、原因を調べ、書き換えて助ける。
- コードの知識がなくても、会話と観察で解ける。遊ぶうちに自然とHTML/CSSが分かってくる。
- トーンは**切ない寄り**。犠牲を伴いながら、大切な人を守る物語。

### 既存作品との違い

- *Super Markup World*(HTML/CSSで足場を作って進むアクションパズル)とは別物にする。あちらは「足場を作って進む」、こちらは「困っている人を助ける物語」。コードは目的ではなく手段。
- 参考:CSS Puzzle Box(JSなしのHTML/CSSパズル集)、Baba Is You(ルールの文字を書き換える)、Untrusted(コードを書き換えて脱出する)、Flexbox Froggy / CSS Diner(CSS学習系)。
- 「住人の物語があり、コードを触ると世界が変わり、それが謎解きになる」という組み合わせは少ないと考えており、ここが狙い目。

## 2. 世界観・ストーリー(たたき台)

- 舞台は、2000年代風の古い個人ホームページ。管理人が更新をやめて久しく、世界がほころびてきている。
- 実は「サーバー閉鎖」が迫っているが、住人たちは気づいていない。プレイヤーだけがその事実を知る。
- 閉鎖の理由は、**管理人がいなくなり、サーバーやドメインの更新をする人がいないこと**。誰も悪くない。
- 管理人が残した**コメントアウト`<!-- -->`**が日記のように少しずつ読め、物語の手がかりになる。
- 終盤は、住人たちを新しいページへ**引っ越し**させる。
- 引っ越し先には**容量(文字数)制限**があり、全員は運べない。最後の文字が一文字足りず、誰かが犠牲になる。

### 2.1 管理人と日記

- 管理人は**すでに亡くなっている**設定。ただし、ゲーム内で「亡くなった」とは**はっきり書かない**。日記が途中で途切れる、最後の日付が古い、などでプレイヤーが自分で気づく形にする。
- 管理人の日記は、**コメントアウト`<!-- -->`**で読める。パズルを解くたびに一つ読める形にして、ソースを見る動機にする。
- 日記は**明るいトーン**で書く。住人を観察して「こいつはこういうところがあるな」と楽しそうに書く。明るいほど、途切れた時に刺さる。
- 管理人の遊び心の例:**マウスカーソルを追いかけるのが好き**。住人がカーソルを追いかける動きの理由が、あとで日記で明かされる。**追いかけるのは全員ではない**(追いかける子・追いかけない子・途中でやめる子がいて、性格の見せどころにする)。
- 住人の顔の文字は、管理人が**一文字ずつ打って作った**ことにできる(犠牲の理由=その文字として残る、と繋がる)。
- 管理人は`</html>`を**打たないまま更新をやめた**。世界がずっと開きっぱなしだった理由になり、最後にプレイヤーが閉じるのは、管理人が打てなかった一文字を引き継ぐ形になる。
- 「死んだ人」ではなく「この世界を作った人」として愛着が湧くよう、管理人自身の日常や遊び心を丁寧に描く(型にはまった悲劇に見せない)。
- 住人たちは、管理人のことをたまに話す。住人にとっては神様でも親でもなく、**「昔いた誰か」「あの人」くらいの距離感**。住人が語る管理人像と、日記の管理人像が少し食い違い、プレイヤーだけが両方を知る。

### 2.1.1 管理人の人物像(決定事項)

- **おじいさん**。元エンジニアで、定年後の暇つぶしにホームページを作った。
- ペットを飼う感覚に近く、住人たちをホームページの上に作り上げただけ。ページ自体に「内容」(趣味の紹介や日記サイトとしての目的)はない。住人がいることが、このページのすべて。
- **名前は出さない**。住人たちは「管理人」と呼び、プレイヤー(主人公)も「管理人」と呼ぶ。
- 途中で更新頻度が下がり、入院していたのかなと思わせる日記があって、帰ってこないのは亡くなったからだと**察せる**流れにする(はっきりは書かない。2.1 の方針どおり)。

- 家族: **奥さんはいたが、いなくなった**(くわしくは後で)。**子どもも孫もいない**。だから、管理人がいなくなったあと、サーバーやドメインを更新する人がいない。

### 2.1.2 日記のトーン(下書き・トーンは決定)

元エンジニアらしい乾いたユーモアで、住人を楽しそうに観察する。日付の間隔がだんだん空き、「病院の待ち時間」→「しばらく更新できないかも」→「消灯」「開かない窓」で入院を察せるようにする。最後の日記は日付も途中で、`-->` で閉じていない。細かい中身はあとで詰める。

```html
<!-- 2009/04/01
  定年して三か月。家にいると落ち着かないので、ホームページを作ることにした。
  今どきは、どこかの会社のサービスを使うらしいが、性に合わない。
  エディタで一から打つ。昔取った杵柄、というやつだ。 -->

<!-- 2009/04/03
  最初の住人を作った。h。
  作ったそばから、ため息をつかれた。「先が思いやられる」そうだ。それは、こっちが言いたい。 -->

<!-- 2009/05/20
  w がまた笑っている。何がおかしいのか聞いたら、余計に笑った。
  バグではない。仕様だ。 -->

<!-- 2009/08/11
  マウスを動かすと、何人かついてくる。
  面白くて、つい画面の端から端まで動かしてしまう。
  h は、ついてくるふりをして、途中でやめる。 -->

<!-- 2011/02/14
  ひさしぶりに。病院の待ち時間が長い。
  帰ってから、みんなの様子を見た。変わりなし。よしよし。 -->

<!-- 2011/09/03
  しばらく更新できないかも。待っててね。 -->

<!-- 2011/11/27
  消灯の前に少しだけ。持ちこんだノートで。
  窓の外ばかり見ている。ここの窓は、開かない。 -->

<!-- 2012/01/08
  最後に、一人。
  名前は、帰ってから考える。 -->

<!-- 2012/02/
  また今度
```

📝 年代(2009〜2012年は仮)と、ゲームの中の「今」が何年か。奥さんのこと(日記にどう出すか)。

### 2.2 住人はプレイヤーを管理人だと思っている(決定事項)

- 住人たちは、**プレイヤーを管理人だと思って接してくる**。「やっと帰ってきたの?」のように。
- プレイヤーは最初「?」となるが、日記を読むうちに、少しずつ事情が分かっていく。
- カーソルを追いかける住人は、それを管理人のカーソルだと思っている(追いかけない子もいる)。
- 会話の選択肢は「うん、ただいま」「……ただいま」のように**曖昧なものだけ**にする。真実を伝える選択肢は出さない。**プレイヤーが優しい嘘をつく共犯**になる。
- **住人には、管理人がいなくなったことを最後まで伝えない**(決定事項)。プレイヤーだけが知っていて、黙っている重さが切なさになる。
- 引っ越しも「新しい家に引っ越そう」という言い方で誘導する。
- 犠牲になる子も、管理人がいないことを知らないまま、閉じタグとして残る。
- 余白として、住人は途中でプレイヤーが違う人だと気づいているかもしれない、と匂わせつつ、それでも「おかえり」と言い続ける案もある(任意)。
- 引っ越し先でも、管理人が来るのを待ち続ける住人がいる最後の画面を、余韻にする案もある。

### 2.3 「先が短い」ことの暗示案

病名や「入院」は書かず、ウェブらしい小道具で暗示する。軸にする案と、数個だけ使う案に分ける。

**軸にする案**
- **閉じられていないコメント**:最後の日記が`<!--`で始まるが、`-->`で閉じられていない。途中で止まった感じが、閉じタグを打たなかった`</html>`とも重なる。
- **止まった更新日**:ページ下の「最終更新日」が、ずっと同じ日付のまま。
- **最後に作った`v`**:最後に作った住人を`v`にする。管理人の最後の作品が、最後に`>`になる。**日記には「閉じ括弧みたいな子」とは書かない**(`v` と `>` のつながりは、プレイヤーが自分で気づく)。

**数個だけ使う案**
- 日記の日付の間隔が、毎日 → 数日おき → 月に一度、と空いていく。
- 文章がだんだん短くなり、ひらがなや「また今度」が増える。
- `<!-- TODO: ... -->`が増えて未完のまま。パズルの中に、TODOを回収する形のものを混ぜる。
- 訪問者カウンターで、管理人が来なくなってから、キリ番を踏むのはプレイヤーだけ。
- 病院を匂わせる程度の一文(例:「窓の外ばかり見ていた」「消灯の前に少しだけ」「しばらく更新できないかも。待っててね」)。

全部入れると重くなるので、軸にする案を中心に、残りは数個だけにする。

### 2.4 気づかせるタイミング

- 序盤:「やっと帰ってきたの?」で、プレイヤーが違和感を持つ。
- 中盤:日記を読んで「あれ?」と思う。
- 終盤:確信する。ただし、直接は言わない。

## 3. 犠牲(結末)の設計

### 3.1 核となるアイデア

- ゲーム内エディタに「残り容量」メーターを置き、入力できる文字数を制限する(世界の設定として実装。HTML自体に文字数制限はないが、ゲーム側のルールとして作る)。
- 最後に、どうしても一文字足りず`</html>`が打てない。**その文字をモチーフにした住人が、代わりにそこへ残る**(犠牲になる)。
- 完成したページの**ソースを開くと、犠牲になった住人が顔付きの文字として残っている**。魚拓(アーカイブ)のような演出。

### 3.2 選択の方針

- 犠牲になる人はプレイヤーが選べる。ただし全員の中からではなく、**推されやすそうな2キャラのどちらか**を選ぶ形、または**誰が犠牲になっても嫌だと思える選出**にする。
- **正解を作らない**:能力や便利さで差をつけず、感情の重さだけが違うようにする。
- 二人とも「自分が行く」と言い出す場面を作る。選ばなかった方にも想いが残る。
- どちらのルートも同じくらい美しく、同じくらい喪失がある。結末の差分は最後の数分に集中させる(9割は共通)。

### 3.3 「どっちを選んでも嫌」にするコツ

- 一方は「プレイヤーの隣にいた相棒(案内役)」、もう一方は「みんなの心の支え」のように、**役割の種類を変える**。
- AはBを、BはAを守りたがっている、という**相互の想い**を用意する。
- 選ぶ前に、それぞれの個人エピソードと最後の願いを回収しておく。

### 3.4 `v`が横を向いて`>`になる(確定したい案)

- `・v・`の子が90度横を向くと`>`になる。可愛い仕草が、そのまま「文字になる」瞬間になる(CSSの`transform: rotate(90deg)`で表現できる)。
- 伏線:序盤は「眠くなると頭が横に傾く」「話を聞くと首をかしげる」といった癖として登場させる。序盤のパズルで一度だけ橋や矢印の代わりになって、戻ってくる。終盤は、戻らない。
- 性格の方向性(案):前向きで人を励ますキャラにして、最後に黙って横を向く切なさを出す。
- 注意:`v`が`>`を担当するため、`<`や`>`をモチーフにした別キャラは作らない(`v`の特別感が薄れるため)。

## 4. キャラクター

### 4.1 見せ方(決定事項)

- 住人は**約10体**。**最初から全員いる**(途中で増やさない)。
- 普段は**頭頂部だけが見える**状態でページ内を移動する。
- 話しかけると**画面の手前(ユーザー側)を向き**、顔が見える。可愛さとギャップを出す。
- 顔は**ローマ字+記号**で作る(例:`・v・`)。テキストで表示すれば、ソースを開いた時に顔がそのまま残る。
- 顔だけでなく、**頭の形・髪型・色・動き方**で、頭頂部の状態でも見分けられるようにする。
- 今話せる子の頭の上に、小さな印(`!`など)を出して導線を整理する。

### 4.2 顔の案(10体・たたき台)

性格は未決。顔から入って、後付けで決めていく。

| 顔 | 性格の仮案 |
|---|---|
| `・v・` | 前向きで励まし役(最後に`>`になる子) |
| `・w・` | 笑い上戸でふざけがち |
| `・u・` | のんびり眠そう |
| `・o・` | 驚きやすく好奇心旺盛 |
| `・m・` | ツンデレで口がへの字 |
| `T_T` | 泣き虫(Tが目になっている) |
| `-h-` | ため息が多い苦労人 |
| `・x・` | 口をチャックしている無口 |
| `・l・` | 鼻が高い自信家 |
| `^e^` | いつもにこにこ |

### 4.3 犠牲の候補2人(決定事項)

- **`・v・` と `-h-`**。
- `-h-` は、管理人が**いちばん最初に作った住人**(`<html>` を打ちはじめた最初の文字が `h`)。`・v・` は、**いちばん最後に作った住人**。二人は管理人の最初の作品と最後の作品。
- 役割のちがい:
  - `・v・`: プレイヤーの隣にいる相棒(案内役)。前向きで励まし役。いちばん新しい子なので管理人のことをあまり知らず、プレイヤーを管理人だと信じきっている。
  - `-h-`: みんなの心の支え。ため息の多い苦労人で、住人の面倒を見てきた最年長。いちばん古い子なので、プレイヤーが管理人ではないと気づいているかもしれない(2.2 の「余白」はこの子に任せる)。それでも「おかえり」と言い続ける。
- 相互の想い: `-h-` は管理人が最後に残した `v` を守りたい。`v` はずっとみんなを支えて疲れている `-h-` を休ませたい。最後に二人とも「自分が行く」と言い出す。
- 文字: 容量があと1文字足りず、`</html>` のどれか1文字が打てない。`>` を残せば `v` が横を向いて `>` に、`h` を残せば `-h-` が `h` の場所に立つ。

### 4.4 二人のエピソードと最後の願い

**`・v・`(最後の子・相棒)**
- 話し方: **幼さを出す**(くわしくは下の「話し方」)。
- 癖と伏線: 眠くなると頭が横に傾く。話を聞くと首をかしげる。序盤のパズルで一度だけ横を向いて `>` になり、矢印の代わりに道を示し、「えへへ、首がこった」と戻ってくる。終盤は戻らない。
- 個人エピソード「名前のない子」: 日記の中で、名前をつけてもらう前に日記が途切れている。ほかの子には名前があるのに、`v` だけ「最後に、一人」のようにしか書かれていない。`v` は気にしていない顔で「管理人さんが帰ってきたら、名前をつけてもらうんだ」と言い、プレイヤーに何度か「名前、考えてくれた?」と聞く。
- **名前はプレイヤーが入力してつける(決定事項)**。中盤のどこかで入力の場面を作る。
- 最後の願い: 「`-h-` に、ちゃんと休んでほしい」「名前を呼んでほしい」。最後に横を向く前に、つけてもらった名前を呼ばれて答える。

**`-h-`(最初の子・心の支え)**
- 癖と伏線: ため息が多い。でも、だれかが困っているといちばんに気づく。ページのいちばん上(`<html>` のすぐ下)に住んでいて、住人の様子を毎日見て回る。
- 個人エピソード「最初の日の約束」: 管理人と最初に交わした約束「みんなをよろしく」を、管理人がいなくなってから一人で守ってきた。日記の最初のほうに、管理人と `-h-` の明るいやりとり(例:「最初の子は、作ったそばから、ため息をつかれた。『先が思いやられる』そうだ。それは、こっちが言いたい」)。
- **プレイヤーが管理人ではないと気づいているかもしれない余白を入れる(決定事項)**。**はじまりの場面で、みんなが「おかえり!」と寄ってくる中、`-h-` だけ、みんなに合わせて少し遅れて「……おかえり」**(5.3)。
- 最後の願い: 「`v` を、ずっと先まで連れていってあげてほしい」。`-h-` を残す結末では「約束、ちゃんと守れたかな」とだけ言う。

**二人が両方「自分が行く」と言う場面(案)**
- `v`: 「`h` はずっとがんばってきたんだから、今度はぼくの番だよ」
- `-h-`: 「最初に作られた者が、最後を閉じる。それが筋だろう」

### 4.5 住人10体(決定事項)

名前は、管理人(元エンジニア)が、**顔の文字から始まるエンジニアの言葉**でつけた。`v` だけ名前がなく、プレイヤーがつける。
カーソルを追いかけるのは全員ではない。表の「出番」は最初の案で、**問題の並びは 5.3 を正とする**。

| 顔 | 名前 | もとの言葉 | 性格 | カーソル | 出番(仕掛け) | つながり |
|---|---|---|---|---|---|---|
| `-h-` | ヘッド | head(先頭) | ため息の多い苦労人、最年長、心の支え | ついてくるふりをして、途中でやめる | ― | 最初の子。4.3・4.4 |
| `・v・` | (プレイヤーがつける) | ― | 幼い、前向き、励まし役。相棒 | 追いかける | 回す・動かす(2回目。最後に横を向いて `>`) | 最後の子。4.3・4.4 |
| `・w・` | ワーカー | worker | 笑い上戸。伝言を運んで走り回る配達係 | 大喜びで追いかける | 時を止める(1回目) | `v` の遊び相手 |
| `・u・` | アップタイム | uptime | のんびり、いつも眠そう(名前は管理人の冗談) | 追いかけない(寝ている) | 隠れた住人を探す(1回目。物の裏で寝ている。`z-index`) | `v` の昼寝仲間。`v` の首が傾く癖はうつった |
| `・o・` | オーバーフロー | overflow | 好奇心旺盛、驚きやすい。ページの外を知りたがる | 追いかけて、いつも行きすぎる | 箱からはみ出して出られなくなる(`overflow`。候補) | 引っ越しにいちばんわくわくする |
| `・m・` | マージ | merge | ツンデレ、口がへの字 | 追いかけない(横目で見ている) | 線を消す(1回目。川でエコーと隔てられている) | ヘッドには素直に甘える |
| `^e^` | エコー | echo | いつもにこにこ。ひとりのときは笑っていない | ゆっくりついてくる | 線を消す(1回目。マージに会いたい) | みんなのお姉さん役 |
| `T_T` | テンプ | temp(一時的) | 泣き虫 | 追いかけない | 隠れた住人を探す(2回目。コメントアウトされている) | ヘッドがいちばん気にかけている |
| `・x・` | クロス | cross(✕。x の形) | 口にチャックの無口。話すかわりに看板や札に字を書く | 少し離れてついてくる | 文字を打ち換える(1回目。この子の看板「立入禁止」) | `v` の名前を考える場面で手伝う |
| `・l・` | リンク | link | 背が高い自信家。「任せろ」が口ぐせ | 追いかけない(自分が先頭のつもり) | 回す・動かす(1回目。横になって橋になる) | 4章の「あと1文字足りない」で穴埋めを引き受けて戻ってくる |

**テンプがコメントアウトされている理由(決定事項)**: 管理人は入院する前に、泣き虫のテンプだけをコメントアウトした。自分が帰らない間、テンプはずっと泣いて待つだろうから、「寝かせておく」ことにした。コメントアウトは、テンプにとって眠っているのと同じで、待つ時間を味わわずに済む。プレイヤーがコメントを外して起こすと、テンプは管理人が出かけたのは昨日だと思っていて、「おかえり!早かったね!」と言う。管理人の残した TODO を、プレイヤーが代わりに片づける形。

```html
<!-- 2011/09/02
  しばらく出かける。テンプは待つのが苦手だから、寝かせておく。
  帰ったら起こす。 -->
<!-- TODO: テンプを起こす -->
```

**仕掛けの2回目(重いほう)の案**
- 線を消す → 線を引く: 引っ越しの途中で、線を引いてみんなを守る
- 文字を打ち換える → `v` の名前をプレイヤーが打つ
- 隠れた住人を探す → コメントアウトされたテンプを起こす
- 時を止める → 📝 未定(カウンターや最終更新日など「止まっている時間」とつなげる案)
- 回す・動かす → `v` が横を向く最後の場面

### 4.6 未決事項

- `</html>`の各文字(`<` `/` `h` `t` `m` `l` `>`)を、必ずしも全てキャラに割り当てる必要はない。**`t`の子は足さない**(決定)。犠牲の候補となる2人が、担当できる文字を持っていれば成立する。
- `v`・ヘッド以外の個人エピソード。

## 5. ゲームデザイン

### 5.1 仕掛け

仕掛けの種類は、下の5つが中心。回数は決めず、問題の並び(5.3)に合わせて使う。**同じ仕掛けでも、あとで出てくるときは前より重い意味で再登場**させる(例:線を消して会わせた二人を、後で線を引いて守る)。

| 仕掛け | 主なコード | 例 |
|---|---|---|
| 線を消す・引く | `border`、`display` | 川で隔てられた二人を会わせる/はみ出しそうな子を線で守る |
| 文字を打ち換える | `contenteditable` | 看板の「立入禁止」を書き換えて道を開く/`v` の名前を打つ |
| 隠れた住人を探す | `z-index`、`display`、`hidden`、コメント | 物の裏で寝ている子を見つける/コメントアウトされた子を起こす |
| 時を止める | `animation-play-state` | 走り続ける配達係を止めて話を聞く/見回りを続けるヘッドを休ませる |
| 回す・動かす | `transform`、`position` | ずれた屋根を直す、横になって橋になる、`v` が横を向く |

その他の候補:`overflow:hidden`の箱からの救出、`:has()`/`:checked`/`:target`を使ったJSなしの仕掛け、`dialog`/`details`で開く別の部屋。

### 5.2 進み方と編集(決定事項)

- **章分けはしない**。ページに次々とほころび(問題)が起き、それを直していく。
- **ページが少しずつ広がる**。最初はページの一部だけが見え、ほかは「工事中」。問題を直すたびに、新しい場所とそのソースが開く。先の日記は、まだ開いていない場所に埋まっているので、先には読めない。
- **ソースはいつでものぞける**。日記(コメント `<!-- -->`)は、問題の場所だけでなく、ページのあちこち(住人の近く、飾りの中、CSS の中など)に埋める。問題を直そうとソースを開くと、そこに毎回日記がある。
- **直し終えた場所・開いた場所は、途中でも自由に書き換えられ、ページに反映される**。
  - 書き換えてはいけない所(住人の顔の文字、物語に大事な部分)には鍵をかける。色・大きさ・看板の文字・飾りなどは自由。
  - 元に戻すボタンを用意する(場所ごと/全部)。
  - 開いた場所の中なら、答えにたどりついた時点で、その問題が解けたことにする。
- **書き換えると、住人が反応する**(例:背景の色を変えたら「わあ、ピンクになった!」)。
- **住人をクリックすると、手前を向いて一言話す**。一言は、直した問題の数に合わせて変わる。次の問題に関わる子の頭の上に「!」を出す。
- 編集パネル: 住人や壁をタップすると、そのコードが見える。最初は値のトグルのみ → 慣れたら一部を自分で書く。全部は書かせない。
- 作り: 本物の HTML をそのまま書き換えるより、ゲームの中でページの形(データ)を持ち、それを書き換えて描き直す作りが、壊れにくくセーブしやすい。試作で触り心地を確かめて決める。スマホでも遊べるようにする。
- **ヒントは2つ(決定事項)**:
  - **住人に話しかける**: 問題が出るときは「止めてあげて!」のように**何をしたいか**だけを言う。話しかけると、その子らしいやり方で手伝う(`v` は方向だけ応援、リンクは自信満々にずれたこと、アップタイムは寝言で意外と核心、**ヘッドはほとんど答え**。ヘッドは管理人がコードを書くのをそばでずっと見ていた)。
  - **別のタブの解説ページ**: 画面はブラウザの窓の形で、タブは住人のページと、主人公が調べものに開いた HTML・CSS の解説ページ。解説ページには、その問題に使うものの説明と、そのまま使える答えのコードが載る(問題が進むと項目が増える)。詰まらないための安全網。
- **サーバー閉鎖のお知らせは、主人公のメールのタブに届く(決定事項)**(問題10)。プレイヤーだけが知る。
- 本物のDevToolsは、裏ルートや上級者向けの隠し要素として取っておく(任意)。
- 容量メーターは、引っ越し先が見つかったところ(問題13)から表示する。

### 5.3 問題の並び(たたき台)

プレイ時間の目安は1.5〜2時間(1問5〜6分)。1つ前の問題が、次の問題のきっかけになるようにつなげる。1つの問題に関わる住人は、2〜5人を混ぜる(`v` かヘッド+主な子、の形ばかりにしない)。

**はじまり**: ページに入ると、起きている子・画面にいる子たちが「おかえり!」「ひさしぶりだね!」と寄ってくる。**ヘッドは閉鎖も管理人のことも、もう知っている**が、みんなに合わせて、少し遅れて「……おかえり」(キャラの紹介と伏線を兼ねる)。

| # | ページのほころび | 関わる住人 | つながり |
|---|---|---|---|
| 1 | `v` の色が消えかけている(はじめての操作。値を1つ戻すだけ) | v・h・w | ヘッド「まず、そいつを直してやれ」。走り抜けるワーカー |
| 2 | ヘッドの家の屋根がずれて雨もり | h・v・l・u | リンクが「任せろ」と支えようとして、背が高すぎて失敗。軒下でアップタイムがぬれながら寝ている |
| 3 | 配達係ワーカーが止まらない | w・v・e | ワーカーは、エコーからマージへの手紙を持ったまま、止まれずに走り続けていた |
| 4 | 川で、マージとエコーが会えない | m・e・w・v | 3の手紙で、二人が川で隔てられていると分かる。ワーカーの手紙が、二人の唯一のつながりだった。**(決定事項 2026-10-08)マージは、お堀に囲まれた小さなお城にいる(「住人たち」の下。はじめは見えない)。すねたマージが「ひとりになりたい」と言い、管理人が城と堀を作った。「出たくなったら言え、橋を作ってあげるから」と言ってあったが、管理人が来なくなり、出られなくなった。お堀は、お城の箱の `border`。ぐるっと囲んでいるので回りこめない。ワーカーは、渡れないので、お堀のまわりを走り続けている。エコーは、はじめからお堀の外に立って、動かずにお城を見つめている(ひとりのときは笑っていない)。手紙も届かないまま、もう長いこと会えていない。`border: none` などで堀を消すと、会える** |
| 5 | アップタイムが見つからない | u・v・x・o | クロスの看板の裏で寝ていた。いびきに気づくのはオーバーフロー |
| 6 | 看板「立入禁止」で道がふさがれている | x・h・o・v | 看板を立てさせたのはヘッド。理由を聞いても「……いいから」 |
| 7 | オーバーフローがページの端から落ちそう | o・h・e・l | 6で開いた道の先に、オーバーフローが走っていってしまう。線を引いて守る |
| 8 | 橋のない谷を越えたい | l・v・w・u | リンクが横になって橋に。みんなで渡る |
| 9 | `v` が首を傾けて `>` になり、道を示す。「えへへ、首がこった」と戻る | v・u・h | ヘッドだけが、それを見て少しだまる |
| 10 | サーバー閉鎖が分かる。看板の奥に「契約期限」の古い貼り紙、同時に主人公のメールのタブに「契約期限のお知らせ」が届く。プレイヤーだけが閉鎖を知る | h・x | 6の看板で隠していたのは、これだった。ヘッドは前から知っていて、みんなをこわがらせないよう隠していた |
| 11 | `v` の名前をつける | v・x・e・w・m | みんなが名前の案を出してくる。決めるのはプレイヤー。クロスが字を書く |
| 12 | コメントアウトされたテンプを起こす | T・h・v・e | テンプ「おかえり!早かったね!」。ヘッドは何も言わずに目をそらす |
| 13 | 引っ越し先が見つかる。容量メーターが出る | v・h・o・l・x | オーバーフローは大喜び。ヘッドは黙ってメーターを見ている |
| 14 | 見回りを続けるヘッドを止めて、休ませる | h・v・T・m | テンプとマージが心配して、`v` がプレイヤーに頼みに来る |
| 15 | 「あと1文字足りない」の冗談 | l・o・w | リンクが穴埋めを引き受け、戻ってくる |

| 17 | 最後の1文字。`v` が横を向くか、ヘッドが残るか | v・h(みんなが見守る) | |

- 出番の数: `v` 13回、ヘッド 12回くらい。ほかの子も2〜6回ずつ。
- 1〜9: 明るい日常の修理。日記も楽しい時期。9で、`v` が `>` になって戻ってくる伏線。
- 10〜15: プレイヤーだけが閉鎖を知り、日記も病院の話になる。
- 16・17: 引っ越しと結末。

### 5.4 演出の方針

- 序盤は犠牲なしで助けられる。ここで住人と仲良くなる。
- 問題に関わっていない子たちも日常を生きていて、反応したりヒントをくれたり、後日お礼を言いに来る。
- 問題の合間に、ささやかな日常の会話を入れる(日常が愛おしいほど、失う場面が効く)。
- 犠牲の操作は、プレイヤーが**自分の手で打つ**(例:閉じタグの文字を入力する、要素を消す)。軽い操作だからこそ重い。消した住人は、自分の手で消したと分かるようにログに残す。
- 序盤の小さなパズルとの**対比**を終盤で使う(戻ってこられた体験 → 戻れない)。
- 選ばなかった方は同じページに残るが、背景が少し暗くなるなど世界の色が変わる。

## 6. 制作方針

- **一人で制作**する。
- 当初はHTMLの勉強用も考えていたが、**ストーリー重視の作品として作る**方向にする。作りながらの学び(閉じタグ、`contenteditable`、`MutationObserver`、`animation`など)も得られる。
- キャラは文字と色で作れるので、画像素材はほぼ不要。
- 結末の分岐は最後の数分に集中させ、制作量を抑える。
- 最初は**プロローグ+1章**だけの小さな試作で、触り心地を確かめてから全体に広げる。
